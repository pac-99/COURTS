# COURTS 2.0: what changed and how Roboflow fits

## Two tracks, one app
Switch with the toggle in the header, or deep-link with `?track=vision` / `?track=community`.

| | Vision track | Community track |
|---|---|---|
| Source of truth | Camera frames run through a Roboflow detection model | Player check-ins, weighted by recency (35 min decay, 2 h window) |
| Fallback | Courts without a camera use community reports | None (no reports = "No data") |
| Extra screens | Vision Lab, live camera panel per court | none |
| Risk it removes | "Will people actually check in?" | "Do we have cameras?" |

Both tracks feed the same status model: occupancy = players / (courts x players-per-court). Under 40% Open, 40-85% Busy, 85%+ Full.

## Roboflow pipeline (Vision Lab)
Camera -> frame every 2-3 s -> Roboflow model (`serverless.roboflow.com/{model}`) -> count class `Player`/`People` above a confidence threshold -> occupancy -> status on the map. Only the count leaves the camera.

- Real, recorded Roboflow outputs ship with the app (5 court photos), so the demo works with no key.
- Add a Roboflow key in the Lab to run live on your own photo, video or webcam.
- "Send reading to map" publishes the count to a court, as a camera would in production.
- Photo check-ins in either track can use the same model to suggest a crowd level.
- Models used (public, Roboflow Universe): `basketball-court-ecb9s/2`, `pickleball-people-detection/1`, `tennis-court-checker/13`.

## Prototype limits (be upfront in the pitch)
- The camera wall is simulated. The Lab detections on sample photos are real model output.
- Community reports are seeded demo data plus anything you submit; state lives in the browser.
- No accounts. Google sign-in from v1 was removed because it needed a client ID.
- Public models are small and trained on few images. For production, train on real footage from your own courts (Roboflow: upload frames, label players, train RF-DETR or YOLO, swap the model id).

## PRD updates suggested
- Goals: replace "10% premium conversion" with a Vision-track metric: counting accuracy (MAE of players vs human count) under 1.5 per court.
- Risk table: add "Model accuracy drops with camera angle/lighting" (mitigation: per-site fine-tuning, active learning in Roboflow).
- Privacy: add on-site signage, DPA with operators, DPIA for EU, counts-only storage.
- Validation plan: run both tracks at one court for 2 weeks and compare against a human count.

## Production path
1. Pick 1-2 pilot courts, mount a PoE camera, point it at the courts.
2. Roboflow Workflow: model + (optional) zone/line counter, run on Roboflow serverless or a small on-site device.
3. Post counts to a backend (Supabase/Firebase); the app subscribes to changes instead of simulating.
4. Active learning: send low-confidence frames to the labelling queue, retrain monthly.
